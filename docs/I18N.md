# Languages in the app (i18n)

The app speaks English and Hindi. This page is for whoever adds a word, a screen or another language.

## How it works in one minute

- All app text lives in two files: `src/i18n/en.ts` (the source of truth) and `src/i18n/hi.ts`.
  Both are one nested object; a key is its path, e.g. `"auth.login.title"`.
- Keys are typed from `en.ts`. A key missing in `hi.ts`, or an extra one, is a TypeScript error, so `npx tsc --noEmit`
  catches it.
- In a component: `const { t, lang } = useT();` then `t("common.retry")`, `t("cart.each", { price: 40 })`.
- Pure logic (no React) takes the language as the last parameter and defaults to English:
  `harvestLabel(date, today, lang)`, `formatLastUpdated(ts, now, lang)`, `buildOrderSteps(events, status, lang)`.
  Keep new logic like that so the Node tests can run it.
- The chosen language is stored on the device under `sgkrashi.language`. Logout, account deletion and a forced logout
  never touch it (tests check this). First start: Hindi if the phone's language is Hindi, otherwise English.
- The switch is on the Settings screen (gear at the top right of Profile) and, for signed-out people, in the corner of the
  Login screen.

## Error messages

The app never shows the server's own error text, an error code, an HTTP status number or a library's text, in English
or Hindi. A failed request goes through one pure function, `friendlyError(error, context)` in
`src/i18n/friendlyError.ts`, which reads only the stable **code** and **status** and returns a message key; screens
call `errorText(err, "login")` (from `useT()`) to get the translated sentence. Unmapped errors get the screen's own
friendly fallback. The original error is logged with `console.warn` in development builds only.

The server's error body is `{ success: false, error: { code, message, details[] } }`. The API client
(`src/api/client.ts`) turns it into `{ code, message, details, status, retryAfterSeconds? }`; a failure with no HTTP
response at all (no connection, DNS, timeout) becomes `code: "NETWORK_ERROR"`; a reply that is not our JSON (a proxy or
CDN error page) becomes `code: "HTTP_ERROR"` with its status.

| Server code (status) | Where it matters | Message |
|---|---|---|
| NETWORK_ERROR (no response) | everywhere | No internet connection or the connection is slow. Please try again. |
| INVALID_CREDENTIALS (401) | login / delete-account password | Wrong email or password (and a hint to verify a new account first) / That password isn't right |
| GOOGLE_ONLY_ACCOUNT (401) | login | This account uses Google to sign in |
| INVALID_GOOGLE_TOKEN, GOOGLE_SIGN_IN_NOT_CONFIGURED | Google | Google sign-in didn't work... |
| INVALID_OTP (400) | OTP | That code isn't right or has expired |
| TOO_MANY_OTP_ATTEMPTS (429) | OTP | Too many wrong codes. Ask for a new code |
| OTP_RESEND_COOLDOWN (429) | resend | Please wait a little before asking for another code |
| INVALID_TOKEN (401), any 401 | everywhere | Your session has expired. Please log in again. |
| ACCESS_DENIED (403), any 403 | everywhere | You don't have permission to do this. |
| RATE_LIMIT_EXCEEDED (429), any 429 | everywhere | Too many attempts... "try again in about N minutes" when the `Retry-After` header is present, otherwise "wait a short while" |
| AI_QUOTA_EXCEEDED, CHAT_QUOTA_EXCEEDED | Crop Doctor / chat | We've reached the limit for this feature for now |
| AI_SERVICE_UNAVAILABLE, CHAT_ASSISTANT_UNAVAILABLE, CHAT_ASSISTANT_DISABLED (503) | Crop Doctor / chat | This feature isn't available right now |
| WEATHER_UNAVAILABLE, GEOCODING_UNAVAILABLE (503) | weather | Weather / place search isn't available right now |
| DUPLICATE_RESOURCE (409) | register / other | This email is already registered / That already exists |
| CONFLICT (409), any 409 | everywhere | This changed while you were working on it |
| RESOURCE_NOT_FOUND, NOT_FOUND (404) | payment / cart / other | We couldn't find that order / This item is no longer available / We couldn't find what you were looking for |
| VALIDATION_ERROR (400), any 400 / 422 | forms | A message for the first field the app knows (email, password, name, phone, otp, address lines, pincode, price, quantity, date), otherwise "Please check the details you entered" |
| VALIDATION_ERROR on a photo upload (413 / 415) | farmer photos | That photo couldn't be used. Choose a smaller photo (under 5 MB) |
| BUSINESS_RULE_VIOLATION (400) | cart / checkout | Some items are out of stock or not available in that quantity |
| BUSINESS_RULE_VIOLATION (400) | delete account | Your account can't be deleted while an order, booking or payout is still in progress |
| BUSINESS_RULE_VIOLATION (400) | payment | The payment didn't go through |
| BUSINESS_RULE_VIOLATION (400) | anything else | We couldn't complete that |
| INTERNAL_SERVER_ERROR (500), any 5xx | everywhere | Something went wrong on our side. Please try again in a little while. |
| anything else | everywhere | The screen's own fallback ("Login failed. Please try again.", ...) or "Something went wrong. Please try again." |

There is no separate server code for "account not verified": a login before the OTP step is answered with
INVALID_CREDENTIALS, so that message also tells a new user to verify their email first.

Tests (`tests/friendlyError.test.ts`) check every row, that all messages exist in both languages, that Hindi mode shows
no English sentence, that the server's own text never reaches the person, the Retry-After formatting, and that no screen
reads `error.message` / `.details` / `response.data.message` to show it.

## What is translated and what is not

| Translated | Shown as the server sent it |
|---|---|
| Labels, buttons, placeholders, empty states, the app's own errors, alerts, banners, tab and header titles, screen-reader labels, dates and "x ago" times | Product / crop / category names, descriptions, reviews, user names, order data, notification titles and messages, chat replies, AI scan results, mandi names, place names, the server's error messages |

Kept in English on purpose (see `docs/I18N_DECISIONS.md`): brand names, units and ₹, the legal pages (Privacy, Terms),
Google sign-in setup hints, Razorpay's own checkout page.

## Add or change a word

1. Add the key to `en.ts` in the right group, then the Hindi to `hi.ts` (same path).
2. Use `t("your.key")`. For `{name}` placeholders pass `{ name }`; the Hindi must use the same placeholders.
3. For a count use a plural object `{ one: "{count} item", other: "{count} items" }` and pass `count`.
   English "one" is exactly 1; Hindi "one" is 0 and 1.
4. If a sentence has a link or bold part in the middle, make it one template with `{terms}` style placeholders and
   split it with `splitTemplate()` (see the Register screen) so each language keeps its own word order.
5. Run `npm test`. It checks: same keys and placeholders in both files, no empty or untranslated Hindi, Devanagari
   present, no unused keys, no key used that does not exist, and no hard-coded English left in `src/`.

If a line is deliberately English (a developer hint, a storage key), end it with `// i18n-ignore` and a short reason.

## Add another language

1. Add the code to `Lang` and `LANGUAGES` in `src/i18n/index.ts`, and the dictionary to `MESSAGES`.
2. Create `src/i18n/<code>.ts` with the type `Messages` (the compiler lists every missing key).
3. Add its month and weekday names in `src/i18n/format.ts`, and a plural rule in `pluralCategory`.
4. Add its name (in its own script) to `LanguageToggle` and `language.*`.
5. Check the layout: Indic scripts need extra line height (`src/i18n/layout.ts`), and no `letterSpacing` on text.

## Layout notes for Devanagari

- Vowel signs sit above and below the line: a `lineHeight` made for English can cut them off. Use
  `scriptLineHeight(lang, fontSize, englishLineHeight)` wherever you set an explicit `lineHeight` on translated text.
- Avoid `letterSpacing` and `textTransform: "uppercase"` on translated text.
- Rows of side-by-side text should wrap (`flexWrap: "wrap"`) or use `flex: 1`, never a fixed width.
- Hindi is usually shorter than English, but some labels are longer (e.g. "भुगतान हो गया"); `tests/i18nLayout.test.ts`
  holds the length limit for tabs, badges and chips.
